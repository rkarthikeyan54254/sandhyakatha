## [P1] Fresh-device sign-in rejects the saved family profile

**Impact:** returning families can sign in and still see an empty family/history. This reproduction does not delete the server copy. The adoption rule can also retain newer previous-account state when a different account's profile is returned.

**Affected code:** `src/App.tsx`, `adoptSynced`; `src/lib/sync.ts`, the anonymous-empty and different-owner return paths.

**Deterministic reproduction:**

1. Store a profile owned by account A, containing one child and one reading, with `updatedAt = 2026-09-12T15:00:00.000Z`.
2. Create a fresh anonymous `emptyProfile()` with `updatedAt = 2026-09-14T02:00:00.000Z`.
3. Mock GET `/api/profile` to return A and its stored profile. Production `syncProfile(fresh)` correctly returns the stored child and older timestamp.
4. Apply the exact App adoption rule:

   ```ts
   Date.parse(current.updatedAt) > Date.parse(next.updatedAt) ? current : next
   ```

5. The newer empty local profile wins; no saved child/history is adopted. The settings-sync effect cannot recover this because local `owner` remains null while `account.id` is A.

**Expected:** restore the authenticated account's history while preserving actual edits made after the request began. A freshly allocated empty profile's clock does not establish an intervening edit.

**Acceptance:** read `docs/PERSISTED-STATE-SAFETY.md`. Cover fresh device, same-account sign-out/sign-in, other-account transition, anonymous local history, genuine edits during a request, and late responses from a prior account. Test App adoption, not only the pure merge functions. Do not replace the predicate with unconditional overwrite.

## [P1] Expired-session 401 permits sign-out to erase unuploaded history

**Impact:** account-owned history recorded after the last successful backup can be cleared without acknowledgement. Session expiry or sign-out in another tab can trigger this. PUT 401 can also falsely indicate a successful backup.

**Affected code:** `src/lib/sync.ts` (`api`, `syncProfile`, `signOut`); `src/App.tsx` (`handleSignOut`); `netlify/functions/signout.mts`.

**Deterministic reproduction:**

1. Start with account-owned local history containing a reading absent from the remote backup.
2. Mock GET `/api/profile` to return 401 and POST `/api/signout` to return 204. The real signout function unconditionally returns 204.
3. Production `signOut(local)` returns `ok`. The only requests are GET profile and POST signout: no PUT occurred.
4. App handles `ok` by allocating `emptyProfile()`. Its save effect replaces localStorage, losing the unuploaded reading.

Also reproduced: GET profile returns 200; PUT profile returns 401. `api` maps 401 to null, and `!put?.stale` resolves `syncProfile` with the unacknowledged candidate.

**Expected:** an anonymous no-op must be distinguishable from expired authentication for account-owned state. An unacknowledged PUT must fail. Preserve local history for reauthentication and retry; never authorize clearing it or claim a completed backup.

**Acceptance:** follow the persisted-state policy, covering GET 401, PUT 401, session expiry between requests, cross-tab sign-out, valid account sign-out, anonymous use, network failure and CAS exhaustion. Verify the stored browser snapshot survives every unsuccessful backup.

## Reproduction method

The harness ran with the existing `vite-node` dependency; no dependencies were installed and no application code was patched. Preserve all existing history and apply the repository's required impact/migration matrix before implementing either repair.
