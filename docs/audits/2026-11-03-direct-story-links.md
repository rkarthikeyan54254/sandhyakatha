# Direct story links with parental opt-in

Reproduction: `/s/rambha-sevenfold-curse/` returns 404 by design because the story is gated. The shelf URL cannot take a WhatsApp reader directly to that story. New `/read/<id>/`, `/read/<id>/hi/` and `/read/<id>/ta/` routes show the exact reviewed title, age and care note, then open the existing shared Reader only after explicit parent consent. They remain noindex and outside the public archive/sitemap. Story prose is fetched only on consent. No new rendering engine or English fallback is introduced.

Persisted-state scope review: this is a stateless direct-entry surface, not a persisted-state repair. It adds no family/account reads, writes, merges, migrations, identification, synchronization or authentication. Entry mounts the existing App unchanged on ordinary routes; direct routes do not mount it. The shared Reader's optional readOnly flag suppresses history-completion/personalization controls only on direct routes. Parental consent is in component memory; it is not written into the family's gate preference. Reload requires fresh consent. Language navigation keeps the exact canonical story and requires consent in the selected language.

Invariants: never assign a reading to an inferred child/account; never change a gate preference because a shared link was opened; never save a false completion; never substitute another story/language/rendition. These routes have no repair or migration behavior and guess no ambiguous identity.

Existing-user matrix: healthy one/multi-child accounts, signed-out local profiles, first/repeated sign-in, different-account reuse, second/stale devices, rename/age/add/delete, conflicting IDs/name+age, concurrent writes and old tabs all retain byte-identical persisted state because no profile/account path is entered. Rollback removes only stateless routes; no stored data needs rollback. Ordinary App remains the existing component and its full safety suite still runs.

Checks: route parsing and malformed URLs; no pre-consent story fetch/render; all three native care/consent flows; shared Reader and Short/Full parity after consent; no history/sync or preference mutation; explicit fetch failures; metadata-only noindex shells, exact native titles/share cards and public archive exclusions. Local full build and test suite are required; GitHub Actions cannot start due to billing, as acknowledged by the owner.
